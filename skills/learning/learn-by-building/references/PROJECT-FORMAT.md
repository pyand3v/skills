# PROJECT.md Format

`PROJECT.md` anchors one build-learning project: the artifact and the capability being developed must be visible together.

## Template

```md
# {Project name}

## Outcome
{The small useful artifact or behavior to build.}

## Learning mission
{What the learner should be able to understand, decide, or do afterwards.}

## Target
- Location: {isolated practice location | repository path | not yet chosen}
- Existing project context: {relevant conventions or none}

## Success criteria
- {An observable behavior or testable property.}
- {A second observable behavior or explanation.}

## Constraints
- {Time, tools, dependencies, compatibility, accessibility, or scope limits.}
```

## Rules

- Keep the outcome narrow enough to reach an observable first increment soon.
- Record a target location precisely once it is chosen; do not infer permission to edit it.
- Update criteria only when the learner materially changes the mission, then preserve why in a learning record.
